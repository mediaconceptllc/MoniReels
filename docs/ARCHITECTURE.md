# Архитектур ба шийдвэрүүд

Энэ файл нь «яагаад ингэсэн бэ» гэдэгт хариулна. «Юу байгаа вэ» гэдгийг
кодоос уншина.

MoniReels анх **Windows ширээний програм** байсан: Flutter бүрхүүл локал
FastAPI процессыг хүү болгон асааж, төслүүдээ дискэн дээр `project.json`-оор
хадгалж, ажлуудаа Python dict дотор барьдаг байв. Тэдгээр таамаг бүр
контейнер дээр буруу — файлын систем түр зуурынх, олон instance зэрэг
хариулдаг, deploy бүр дундуур ажиллаж байсныг арчина.

---

## 1. Медиа хэзээ ч backend-ээр дамжихгүй

Хуулалт нь хөтчөөс R2 руу **presigned PUT**, унших нь **presigned GET**.

Яагаад: 4 ГБ видеог dyno дундуур нэвтрүүлэх нь (а) хүсэлтийн timeout-ыг
давна, (б) процессын санах ойн төсвийг иднэ, (в) ижил байтад ХОЁР удаа
төлбөр гаргана. `app/r2.py` бол энэ дүрмийг барих цорын ганц газар.

### Түлхүүр бол ХАЯГ, татагдах нэр бол ХАРАГДАЦ

Объектын түлхүүр нь `project_id` дээр тогтдог ба **хэзээ ч өөрчлөгддөггүй**.
Төслийн нэрийг «сайхан болгож» түлхүүрт оруулбал нэр солих бүрд байгаа
файлууд эзэнгүй үлдэж, хоёр нэршил мөнхөд зэрэгцэнэ.

Хүн харах нэрийг signed URL бүрд `response-content-disposition`-оор өгнө
(`r2.download_name`) — миграц шаардахгүй, аль хэдийн байгаа файл ч шинэ
нэрээр татагдана. Нэр нь `{Төсөл}-Reel-2.mp4`: төсөл БА дугаар хоёулаа
орно, эс бөгөөс зургаан гарцыг дараалан татахад Downloads хавтсанд
`reel(1).mp4`, `reel(2).mp4` болж, аль нь алины болох нь танигдахгүй.

**Плеерийн холбоост нэр өгөхгүй**: `attachment` нь `<video>`-г тоглуулахын
оронд татуулна. Тиймээс нэг объект хоёр зорилготой бол ХОЁР холбоос гарна
(`play_url`, `download_url`).

## 2. Хүнд ажил үргэлж worker дээр

ffmpeg ба torch хайрцгийг бүтнээр нь эзэлнэ. Тэднийг uvicorn-той нэг
контейнерт тавихад платформын healthcheck хугацаандаа хариу авахаа больж,
сервис **дахин асна** — тэр нь ачааллыг үүсгэсэн яг тэр ажлыг тасалж, R2 руу
явж байсан хуулалтыг ч тасална (тэр нь дараа нь төлбөр тооцуулсан multipart
хог үлдээнэ, `r2.abort_stale_uploads` түүнийг НАСААР цэвэрлэнэ).

### Эгнээ (lane) нь ажлын тоо биш, НӨӨЦӨӨР хязгаарлана

`app/jobs/kinds.py`:

- `LANE_HEAVY` = CPU/RAM бүхэлдээ (ffmpeg, Demucs) — **үргэлж 1**
- `LANE_METERED` = гадаад төлбөртэй үйлчилгээ, өөрийн rate limit-тэй — мөн 1,
  ч шалтгаан нь өөр
- `LANE_NET` = зөвхөн HTTP хүлээлт — давхцуулахад хямд

«Нэг дор хэдэн ажил» гэдэг буруу асуулт: нэг ажил нь HTTP хүлээлт, нөгөө нь
бүтэн CPU кодлолт байхад ижил тоо утгагүй.

### Эрэмбэ нь ХУГАЦААНААС гарна, яаралтай эсэхээс биш

`SECONDS · QUICK · MINUTES · VERY_LONG`. «Хэр чухал вэ» гэдгээр эрэмбэлэх нь
3 секундын дуудлагыг 20 минутын render-ийн ард тавьдаг. Хугацааны
зэрэглэлээр эрэмбэлэхэд дараалал ойролцоогоор «богино нь эхлээд» гэсэн
дарааллаар цэвэрлэгдэж, дундаж хүлээлт багасна. Төлбөртэй эсэх нь эрэмбэд
НӨЛӨӨЛӨХГҮЙ — түүнийг `NO_RETRY` хариуцна.

### `running` төлөв нь амьдын нотолгоо БИШ

OOM эсвэл redeploy-д алагдсан worker `running`-д **цогцос** үлдээнэ, ба тэр
цогцос эгнээгээ мөнхөд хаана. Тиймээс амьд эсэхийг зөвхөн **хөдөлж байгаа
heartbeat** шийднэ (`jobs/queue.py: claim`, `reap_stale`).

### Төлбөртэй ажил дахин оролддоггүй

`transcribe`, `suggest` нь `NO_RETRY`. Нэг оролдлого = нэг төлбөр; дахин
оролдох нь эхний оролдлого аль хэдийн гүйцэтгэсэн байж болох ажлын ХОЁР дахь
нэхэмжлэх.

## 3. Провайдерын давхарга

### OpenRouter — текстийн бүх ажил

Урьд нь OpenAI ба Anthropic хоёр тусдаа клиент, тусдаа түлхүүр, тусдаа
тохиргоо, UI дээр солих товчтой байв. OpenRouter дээр тэр бүхэн **моделийн
нэр** болж хураагдана.

Хоёр хуучин клиентийн хатуугаар сурсан зүйлс АЛГА БОЛООГҮЙ, харин
«моделийн нэрсийн жагсаалт» биш **чадварын шалгалт** болж хувирсан:

- Хязгааргүй `max_tokens` нь провайдерыг моделийн БҮТЭН гаралтын таазыг
  дансны минут тутмын хязгаарт нөөцлүүлдэг — жижиг дансны 429-ийг
  транскриптийн хэмжээ биш ТЭР үүсгэдэг.
- Зарим модел custom `temperature` няцаана.
- Anthropic-т чиглүүлэгдсэн модел `minItems`/`maxItems` > 1 няцаана.

Тус бүрийг ЖИНХЭНЭ алдаанаас нэг удаа илрүүлээд клиентийн насан туршид
санана. Моделийн нэрээр хатуу шүүх нь шинэ модел гармагц хуучирдаг.

### duudlaga.dev — монгол яриа таних

Chimege-ийн адаптерээс **провайдераас хамаараагүй бүхнийг** салгаж
`stt/chunking.py` болгосон: завсраар хуваах арифметик, chunk бүрийн
хилийг санаж текстийг буцаан байрлуулах логик. Тэр нь Chimege-ийг ХЭЗЭЭ Ч
тестлээгүй — тэр нь дуу хаана огтлогдож, буцаж ирсэн текст тэр огтлолууд
дээр яаж тавигдахыг шийддэг математик.

Гол дүрэм: **chunk-ийн `[start, end]` нь ЯГ мэдэгдэнэ, учир нь огтлолыг БИД
хийсэн.** Тиймээс цаг нь өөрсдийн хилээс гарна, провайдераас ХЭЗЭЭ Ч биш.
Зөвхөн нэг chunk дотор текстийг хуваах нь ойролцоо.

#### Алдааны код нь статусаас илүү чухал

duudlaga.dev алдаа бүрийг `code` талбартай JSON-оор буцаана, ба гурав нь
статусаар шүүхэд БУРУУ ажиллана:

- **422 `no_speech` нь алдаа БИШ.** Аль цонхыг явуулахыг VAD сонгодог ба тэр
  нь хөгжмийн цохилт, ханиалга дээр эндүүрдэг. Үүнийг алдаа гэж үзвэл нэг
  муу хоёр секундын цонх бүтэн цагийн транскрипцийг унагаана. Тэр хэсэг
  зүгээр л юу ч оруулахгүй.
- **402 хэзээ ч дахин оролдохгүй.** Дууссан үлдэгдлийг дахин оролдох нь
  ижил алдааг гурав удаа гаргаж, оператор уншиж байх ёстой ганц мөрийг
  булна.
- **429 `daily_spend_cap_exceeded` ч дахин оролдохгүй** — нөгөө хоёр 429
  оролдох ёстой атал. Өдрийн хязгаарыг зөвхөн цаг шийднэ, ажлын наслалтын
  дотор биш.

`Retry-After` толгойг хүндэтгэнэ (сервер цонхоо хэзээ нээхээ мэднэ, бид
мэдэхгүй) — гэхдээ дээд хязгаартай: нэг хэсэг дээр worker-ийн слотыг арван
минут барих нь унаж, дараалалд буцахаас муу. `Retry-After` нь HTTP-огноо
хэлбэртэй ирвэл ердийн backoff руу шилжинэ — огнооны форматыг буруу уншиж
хэдэн цаг унтахаас тэр нь дээр.

## 4. torch суурь image-д БАЙХГҮЙ

CPU-only torch нь ~800 МБ. Тэр нь image-ыг гурав дахин томсгож, cold start
бүрийг удаашруулах бөгөөд — хамгийн чухал нь — контейнерийн cgroup CPU
хязгаарыг УНШИХГҮЙ.

Тэгэхээр `requirements-ml.txt` нь сонголт: VAD (жинхэнэ ярианы цаг) ба
Demucs (хөгжмөөс хоолой салгах) хэрэгтэй worker дээр л суулгана.
Түүнгүйгээр хэлхээ **цэвэр доройтоно** — ffmpeg-ийн `silencedetect`-д
тулгуурласан завсрын хуваалт руу шилжинэ, тэр нь production-д ажиллаж
байсан зам.

`config.heavy_threads` нь `/sys/fs/cgroup`-оос ЖИНХЭНЭ quota-г уншиж
thread-ийн хязгаарыг тавина; `app/worker.py` түүнийг torch импортлогдохоос
ӨМНӨ орчны хувьсагчид бичнэ (torch тэднийг import-ийн үед уншдаг).

**torch байхгүй нь torch-той ХОЛБООГҮЙ зүйлийг унтраах ЁСГҮЙ.** STT рүү
илгээх аудиог 16 kHz моно болгох хөрвүүлэлт `torch_available()`-ийн ард
байсан — учир нь дуудагдаж байсан resampler нь салгалтын модул доторх
torchaudio-гийнх байв. torch зориуд байхгүй тул тэр салаа ХЭЗЭЭ Ч
ажиллаагүй, провайдер эх бичлэгийн 48 kHz стерео авдаг байлаа: секундэд
192 кБ, 59 секундын хэсэг **11 МБ**, ба API яг тэр хэмжээний хэсгүүдэд
500 ба хоосон биетэй 520 буцаадаг байв. Дискретчлэл бол ffmpeg-ийн нэг
мөр, ffmpeg нь энэ image-ийн ХАТУУ шаардлага — нөхцөлдөх зүйл байгаагүй.
`test_the_provider_gets_16k_mono_even_though_torch_is_absent` барина.

## 5. Аюулгүй байдал

- **Эрхийн шалгалт зөвхөн backend дээр.** Frontend товч нуух нь хамгаалалт
  биш. Шинэ endpoint нэмэх бүрд `Depends(current_user)` эсвэл
  `Depends(require_admin)` заавал тавь.
- **Өөр хүний төсөл нь БАЙХГҮЙ мэт харагдана** (404, 403 биш). 403 нь тэр
  төсөл ҮНЭХЭЭР байгааг баталчихна.
- **Токены сериал.** Нууц үг солиход `token_serial` нэмэгдэж, өмнөх бүх
  токен нэн даруй хүчингүй болно. Цагийн тэмдэгээр шалгах нь БОЛОХГҮЙ:
  JWT-ийн `iat` нь секундын нарийвчлалтай тул (а) солилттой ижил секундэд
  гаргасан токен амьд үлдэнэ, (б) солилтын хариуд өгсөн ШИНЭ токен өөрөө
  «хуучин» мэт уншигдаж хэрэглэгчийг тэр дор нь гаргана. Хоёулаа ажиглагдсан.
- **Нэвтрэлт хязгаарлагдсан** (`app/ratelimit.py`). PBKDF2 200k давталт нь
  оролдлого тутам ~100мс CPU иднэ; хязгааргүй бол хэдэн арван зэрэгцээ
  таамаг бүх worker-ыг зогсооно. Энэ нь таамаглал удаашруулахаас ӨМНӨ
  хүртээмжийн хамгаалалт. Нэрийг ҮРГЭЛЖ IP-тэй хослуулна — эс бөгөөс
  халдагч хүссэн бүртгэлээ түгжинэ.
- **Секрет бичдэг HTTP зам БАЙХГҮЙ.** Ширээний хувилбарт `backend/.env`
  рүү бичдэг endpoint байсан. Нэг Windows машин дээр хор хөнөөлгүй,
  нээлттэй URL дээр бол бүрэн эрх алдагдал.

## 6. Хасагдсан зүйлс ба яагаад

| Юу | Яагаад |
|---|---|
| NVENC / QSV / AMF салаанууд, hwaccel шалгалт | GPU байхгүй. Нөлөөгүй сонголт үзүүлж байсан. Software H.264 нь ҮНЭХЭЭР удаан тул `crf`/`preset` нь одоо жинхэнэ хөшүүрэг. |
| `C:/Windows/Fonts` уншилт | Фонт нь image-аас ирнэ. Кирилл дэмждэг эсэх нь Dockerfile-ийн асуудал (`fonts-noto-core`) — байхгүй бол шатаасан хадмал хоосон дөрвөлжин болно. |
| Сул порт өөрөө сонгох, `READY <port>` handshake, 60 сек ажилгүй бол унтрах | Бүгд Flutter эцэг процессын төлөө байсан. |
| `routes_media.py` (`/files?path=`) | Локал файлын сервер. Presigned URL-ээр солигдсон. |
| `routes_settings.py`, `utils/env_file.py` | Дээрх аюулгүй байдлын хэсгийг үз. |
| `mov` контейнер | Reels/Shorts зөвхөн mp4 авдаг. |
| 10 секундын preview render | Ширээн дээр үнэгүй, үүлэн дээр бүтэн ажил. Хөтөч эх видеог clip жагсаалтаар нь тоглуулах нь хурдан ба үнэгүй. |
| Эх видеог төсөл рүү хуулах | Ширээн дээр «төсөл бие даасан байх» нь зөв байсан. R2 дээр энэ нь зүгээр л хоёр дахин их хадгалалтын төлбөр. |

## 7. Хадгалагдсан зүйлс ба яагаад

- **`ai/prompts.py`** — LLM нь секунд БИШ **сегментийн индекс** буцаадаг тул
  зохиомол цаг гаргах нь бүтцээрээ боломжгүй, огтлолт бүр жинхэнэ хилэн
  дээр буудаг. Нэг ч мөр хөндөөгүй.
- **`ai/llm_client.py`** — провайдер солихыг нэг файлын өөрчлөлт болгосон яг
  тэр давхарга.
- **`export/pipeline.py`** — `.part` файлаар бичээд амжилтын дараа нэрлэдэг
  тул унасан render хэзээ ч эвдэрхий файл үлдээхгүй.
- **`models.py`-гийн миграцын шат** — `migrate_project_dict` нь JSONB баганад
  хадгалагдсан документ дээр хэвээр ажиллана.
